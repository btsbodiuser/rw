## 2. Preorder Stock / Quantity Cap

### Decision
- Preorder products with variants (boots, sneakers) need exact per-variant quantity caps because you buy specific counts of each color+size from abroad.
- Products without variants use `products.stock` as the cap.
- **NULL stock = unlimited** (no cap, orders always allowed).
- **Stock set = hard cap** — decrement on order, restore on cancellation.

### Changes

| File | What changed |
|---|---|
| `backend/migrate.php` | Migration 046 — makes `product_variants.stock` and `products.stock` nullable. Backfills existing preorder items to NULL (were 0 by default). |
| `backend/api/orders.php` | Preorder items now check stock if not NULL. `deduct_stock` flag stored per item. In-transaction re-verify updated. |
| `backend/cron/cancel-expired-orders.php` | Restores stock using `WHERE stock IS NOT NULL` — skips unlimited preorder variants. |
| `backend/pages/order-detail.php` | Manual cancel/un-cancel uses same `IS NOT NULL` logic. Removed type=ready check (NULL check handles both). |
| `backend/pages/product-form.php` | Stock field saves empty string as NULL. Hint text: "Хоосон орхивол захиалга хязгааргүй". Variant stock also nullable. |
| `src/app/types.ts` | `ProductVariant.stock` changed to `number \| null`. |
| `src/app/pages/ProductDetailPage.tsx` | `effectiveStock` and `stockToCheck` are `number \| null`. Preorder badge shows "X ширхэг үлдсэн" or "Захиалга дууссан" when stock is set. Quantity clamping respects null. |

### Stock logic table

| Product type | Has variants | Stock value | Behavior |
|---|---|---|---|
| preorder | yes | set (e.g. 5) | enforce per-variant limit |
| preorder | yes | null | unlimited for that variant |
| preorder | no | set | enforce product-level limit |
| preorder | no | null | unlimited |
| ready | any | any | always enforce (unchanged) |

## 3. Product Gallery — Video Upload Support

### Decision
- Videos allowed in **gallery only** (not main image — product cards use `<img>` everywhere).
- Autoplay muted loop on product detail page.
- 50MB max per video.
- No limit on count per product (in practice will be 1).
- Formats: MP4, WebM.
- Detection by file extension in URL (`.mp4`, `.webm`) — no API changes needed.

### Changes

| File | What changed |
|---|---|
| `backend/includes/functions.php` | `uploadMedia()` accepts `video/mp4`, `video/webm`. 50MB limit for video, 10MB for images. Skips `resizeImage()` for video files. |
| `backend/pages/product-form.php` | File input `accept` updated. Gallery thumbnails and media picker grid show `<video preload="metadata">` with play icon overlay for videos. |
| `src/app/pages/ProductDetailPage.tsx` | Added `isVideo(url)` helper. Main gallery renders `<video autoPlay muted loop playsInline>` for videos. Thumbnail strip shows play icon overlay for video items. |

### Server config reminder
`php.ini` needs `upload_max_filesize = 50M` and `post_max_size = 50M` for video uploads to work.

## 4. SMS Provider Migration — MessagePro → CallPro

### Decision
- SMS provider endpoint changed from `https://api.messagepro.mn/send` to `https://api-text.callpro.mn/v1/sms/send`.
- URL-only swap for now; request shape (GET with `from`/`to`/`text` query params + `x-api-key` header) kept identical pending confirmation from CallPro docs.
- DB settings keys (`messagepro_api_key`, `messagepro_from_number`) and UI labels left unchanged to avoid migration churn — to be renamed in a follow-up if needed.

# Session log — 2026-09-05

Full backend + frontend redesign session. Adds a running-store attribute
system, a banner-with-locations system, replaces the entire storefront with
a new Unimart-style design, and drops the redundant `activity_types` feature.

---

## How to sync another PC to this state

```bash
# 1. Pull the repo (or copy the files)
# 2. Point backend/config/database.php at the target DB
# 3. If DB is fresh:
php backend/install.php    # (only if fresh install)
# 4. Always run migrations (idempotent — safe to re-run):
php backend/migrate.php
```

At the end you should see:
```
✅ 066_running_attributes    — Successfully applied
✅ 067_banner_locations      — Successfully applied
✅ 068_drop_activity_types   — Successfully applied
```
or all "⏭️ Already applied" if the DB is already up-to-date.

## 1. DB migrations added (3)

Location: [backend/migrate.php](../backend/migrate.php)

### 066_running_attributes
- `categories.parent_id` (nullable) + index — enables subcategories
- `product_sizes.size_group` enum(`clothing`,`shoes`,`accessories`) + backfill
  (numeric sizes → shoes, letters → clothing)
- New master tables + pivots:
  - `shoe_types`      + `product_shoe_types`      (Road, Trail, Race, Lightweight)
  - `run_types`       + `product_run_types`       (Race, Tempo, Daily, Long)
  - `cushionings`     + `product_cushionings`     (Max, Balanced, Responsive)
  - `gait_types`      + `product_gait_types`      (Neutral, Stability)
- Vocabularies seeded with Mongolian labels

### 067_banner_locations
- `banner_locations` table (slug / label_mn / label_en / description / is_active / sort_order)
- `sliders.location_id` FK column + index
- Seeded 4 locations: `hero_home`, `mid_home`, `shop_top`, `above_footer`
- Backfilled existing sliders → `hero_home`

### 068_drop_activity_types
- Dropped `product_activity_types`
- Dropped `activity_types`
- Reason: fully redundant with `shoe_types + run_types`. Only 4 products
  were tagged, no meaningful data loss.

## 4. Attribute model (final state)

| Attribute | Storage | Values |
|---|---|---|
| Gender | `products.gender` enum | men / women / unisex / kids |
| Category | `categories` + `products.category_id` | Hierarchical (parent_id) |
| Brand | `shops` + `products.shop_id` | Single-select |
| Shoe type | `shoe_types` + `product_shoe_types` pivot | Multi: Road / Trail / Race / Lightweight |
| Run type | `run_types` + `product_run_types` pivot | Multi: Race / Tempo / Daily / Long |
| Cushioning | `cushionings` + `product_cushionings` pivot | Multi: Max / Balanced / Responsive |
| Gait | `gait_types` + `product_gait_types` pivot | Multi: Neutral / Stability |
| Color | `product_colors` + `product_variants.color_id` | Per variant |
| Size | `product_sizes` (`size_group`) + `product_variants.size_id` | Per variant |
| Price | `products.price` / `original_price` | Range filter |

## 5. Banner system (final state)

- `banner_locations` — admin-managed vocabulary of positions
- `sliders` (labeled "Баннер" in admin) — banner rows FK'd to a location
- 4 seeded locations (`hero_home`, `mid_home`, `shop_top`, `above_footer`),
  admin can add more via the "Баннер байршил" page
- Frontend: `getBannersForLocation('slug')` returns all active banners for
  that location, sorted by `sort_order`
- Home hero uses the **first** active banner from `hero_home` — no slider,
  single image only (per user request)

To add a new banner location:
1. Admin → **Баннер байршил** → add row (label + auto-slug)
2. Admin → **Баннер** → add banner, pick the new location
3. In PHP page: `$banners = getBannersForLocation('your_slug');`

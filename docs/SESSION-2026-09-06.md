| File | Purpose |
|---|---|
| [product.php](../product.php) | Single product page — gallery from `image_ids`, brand/rating/price, colour+size variant picker wired to real `product_variants` stock, spec-tag chips, related products |
| [cart.php](../cart.php) + [cart-action.php](../cart-action.php) | Session-based cart (`$_SESSION['cart']`) — add/update/remove, server-side stock capping |
| [login.php](../login.php) + [login-action.php](../login-action.php) + [logout-action.php](../logout-action.php) | Customer login, bridged to the existing `backend/api/auth/login.php` |
| [signup.php](../signup.php) | Phone (OTP-verified *or* direct, per admin setting) + email (OTP-verified) registration |
| [session-bridge.php](../session-bridge.php) | Turns a bearer token from a `fetch()`-based auth flow (signup, social login) into a PHP session |
| [account.php](../account.php) + [account-address-action.php](../account-address-action.php) | Info / Addresses / Orders tabs, backed by `backend/api/addresses.php`, `districts.php`, `customer-orders.php` |
| [brands.php](../brands.php) | A-Z brand directory (see §5) |

### Why these call into `backend/api/*` instead of hitting the DB directly
The backend already had a mature customer-facing JSON API (`backend/api/auth/*`,
`addresses.php`, `customer-orders.php`, `districts.php`) — password hashing,
OTP flow, rate limiting, all already built. Re-implementing that in the
frontend pages would have duplicated (and risked diverging from) working
security-sensitive code. Instead:

- **[includes/config.php](../includes/config.php)** gained `apiCall(method, path, body, token)`
  — an internal cURL bridge from the server-rendered pages to `backend/api/`
- Session-establishing endpoints (`login-action.php`, `session-bridge.php`)
  call the API, then call `loginCustomerSession($user, $token)` to populate
  `$_SESSION['user_id']` / `$_SESSION['user']` / `$_SESSION['customer_token']`
  so the existing `isLoggedIn()`/`getSessionUser()` stubs actually work
- Pages needing customer data (`account.php`) call the API server-side with
  `Authorization: Bearer <customer_token>` from the session

### "Stay Logged In"
- `rememberCustomer($token)` / `forgetCustomerCookie()` in config.php set/clear
  a `rw_remember` cookie (independent of PHPSESSID, 7-day expiry matching the
  API's own `customer_sessions` token lifetime)
- A bootstrap check at the bottom of `config.php` runs on every request: if
  the PHP session isn't logged in but `rw_remember` is present, it silently
  re-validates the token via `auth/me.php` and restores the session — this is
  what makes login survive a closed browser / expired PHP session
- Wired into: the login page checkbox, and defaulted on for every signup path

### Login/register methods are admin-controlled, not hardcoded
`login.php` and `signup.php` read the existing settings from
**Backend → Тохиргоо → Нэвтрэх тохиргоо** (these settings already existed in
the schema/admin UI from an earlier migration, just weren't consulted by the
frontend yet):

| Setting | Effect |
|---|---|
| `login_phone_password_enabled` | Phone shows as a login identifier option |
| `login_email_enabled` | Email shows as a login identifier option |
| `login_phone_otp_enabled` | Signup phone tab uses the 3-step SMS-OTP flow |
| `login_register_without_otp_enabled` | ...falls back to a 1-step phone+password form hitting `register-direct.php` (which was already self-gated server-side by this exact setting — just never had a frontend caller) |
| `register_email_enabled` | Email signup tab is shown |
| `login_google_enabled` / `login_facebook_enabled` | Social buttons shown — **also** requires a non-empty `google_client_id` / `facebook_app_id`, so a half-configured provider never renders a dead button |

If admin somehow disables every method, both pages fail open to phone rather
than dead-ending.

### Social login (Google / Facebook)
Wired to the existing `backend/api/auth/social-login.php`:
- Google Identity Services (`accounts.google.com/gsi/client`) rendering a
  native button; Facebook JS SDK with a custom "Continue with Facebook" button
- Handles the `needs_phone` response (brand-new social account) with an
  inline phone+OTP linking step before finishing via `session-bridge`

## 7. Bugs found and fixed

1. **Stale-code race in email OTP** ([backend/api/auth/send-email-otp.php](../backend/api/auth/send-email-otp.php)) —
   requesting a second code left both valid; verification only checks the
   newest row, so using the first email's code failed with "Invalid or
   expired OTP" even though it *looked* right. Fixed by deleting unused
   codes for that email before storing a new one, and switched expiry to
   `DATE_ADD(NOW(), INTERVAL 10 MINUTE)` instead of PHP's `date()` (matches
   the phone-OTP endpoint's existing pattern, avoids a PHP/MySQL timezone
   class of bug even though both happen to agree in this environment).
2. **`.htaccess` swallowing a POST body** — the global `.php` → clean-URL
   301 redirect turns POST into GET on most browsers. `cart-action` and
   `login-action` were already exempted; added `session-bridge` to the same
   exemption (it's called via `fetch()`, same failure mode).
3. **Theme CSS typo** — `.rbt-login-form-inner` referenced `--colro-white`
   (typo) instead of `--color-white`, so its white card background never
   applied; combined with an unrelated `rbt-shadow-box` class I'd mistakenly
   added (that class is actually a *solid brand-blue CTA box*, not a plain
   card), login/signup rendered as a solid blue box. Fixed by dropping the
   wrong class and patching the typo'd var in each page's own style block.
4. **Invisible multi-word nav labels in the sticky header** — the theme's
   sticky nav row has a fixed `line-height: 86px` sized for single-line
   labels. The two new multi-word items ("Гүйлтийн гутал", "Техник &
   Дагалдах") wrapped onto a second line at their natural width, and that
   line rendered outside the header's clipped bounds — invisible, despite
   every computed style looking completely normal. Confirmed via headless
   Chromium *and* Firefox screenshots plus pixel-sampling (~0% non-white
   pixels where the text should be). Fixed with `.mainmenu > li > a {
   white-space: nowrap; }` in all 8 pages' style overrides.
